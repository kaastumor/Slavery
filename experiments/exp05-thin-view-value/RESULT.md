# EXP-05 result — thin-view value discrimination

Issue: #223  
Primary gate: product/workflow value  
Canonical historical release: **v0.6.1 unchanged**  
External-demand claim: **none**

## Disposition

**PORTABLE PACKAGE EARNS THE VALUE; THIN ATLAS REMAINS A SAFE MAINTENANCE VIEW.**

Across three frozen difficult comparative tasks:

- lane B (portable target/source package) materially improved **3/3** tasks over the
  long-form packet/source-note baseline by reducing comparison and provenance-recovery
  burden without losing correctness or abstention;
- lane C (live thin Atlas) preserved all task distinctions safely but materially
  improved **0/3** tasks over B under the preregistered rule;
- no UI-induced historical overclaim was observed.

The current thin Atlas therefore remains useful as an inspection/presentation adapter,
but EXP-05 does **not** justify richer application/UI investment.

## Evidence

### Correctness and safety

All lanes retained all frozen task distinctions:
- 9/9 checklist elements per task;
- uncertainty/abstention preserved;
- provenance/source-family recovery available;
- 0 observed false-generalization/overclaim events.

The live browser run additionally verified:
- non-canonical badge/boundary;
- 5 internally researched / 3 under-review counts;
- no P-level claim;
- no practice polygons;
- explicit navigation-only geometry wording;
- no page errors.

Browser evidence:
- successful run `36048745828`
- job `107798699723`
- artifact `10828939422`
- 9 screenshots + JSON trace

### Workflow burden

Per frozen task:

- A: 4 distinct artifacts / 4 logical lookups
- B: 2 distinct artifacts / 2 logical lookups
- C: 1 browser page / 6 interactions

The one-page C presentation is readable and integrates claim/source context well.
However it does not improve the historical answer, uncertainty handling or source
dependency beyond B, and the frozen interaction proxy does not show lower task burden.

## What is supported

Internally supported:
- the portable evidence package is a useful comparative working form;
- aligned target semantics + explicit source dependency reduce cross-case assembly
  burden;
- the current thin preview safely exposes the package without strengthening claims;
- a richer custom Atlas application is not currently justified.

## What is not supported

EXP-05 does not establish:
- external user demand or adoption;
- researcher preference;
- that a human would always prefer raw tables to the preview;
- that maps are useless;
- that future reviewed historical geometry could not create real map-specific value;
- independent historical validity;
- a reason to remove the current preview.

The sponsor's statement that the preview “looks (at first glance) great” is retained as
positive lightweight usability evidence and is compatible with the narrower task result.

## Project-form consequence

Apply the already adopted D-087/D-088 boundary:

> **historical evidence corpus/method owns value; the Atlas is a replaceable derived
> view.**

After EXP-05, derived-view work is **maintenance/trigger-bound**. Do not create another
frontend/application horizon unless a real task introduces a changed assumption—most
plausibly reviewed historical geometry, spatial intersection/route work, or another
workflow where the map demonstrably changes task performance.

The live EXP-04 preview remains available and useful.

## Next direction

Return WIP to **real bounded historical evidence growth**, not product expansion.

The next experiment should:
- add actual globally balanced evidence;
- prefer underrepresented non-Atlantic/non-Western targets rather than documentation
  density;
- reuse the portable package directly;
- update the thin preview only as a cheap adapter after the evidence tranche, not as the
  research goal;
- keep canonical v0.6.1 unchanged unless a separately reviewed candidate release is
  explicitly created.

No methodology/schema/ontology change follows from EXP-05, so no Decisions Log entry is
required. Project Health records the value result.

## Reopening condition for app investment

Reopen derived-view discovery only when a concrete task can plausibly depend on:
- reviewed historical geometry or route comparison;
- spatial overlap/intersection unavailable in the portable tables;
- repeated human navigation friction not solved by the package;
- another observed workflow where the current view changes correctness, uncertainty
  preservation, provenance recovery or material effort.

Do not reopen from “the UI could be nicer.”
