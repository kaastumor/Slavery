# DISC-06 comparison — current packet vs minimal inference ledger

**Issue:** #240  
**Input:** six exposed regression cases; no new historical research  
**Frozen threshold:** survive only if the ledger adds material reconstructibility or
revision-impact information in at least two distinct failure mechanisms without mere
duplication.

## Result

**REJECT as a default project abstraction.**

The experimental ledger makes reasoning edges easier to query, but it does not add
material historical/review information that is absent from the current portable packet
for the frozen six cases.

The current packet already preserves the decisive relationship through combinations of:
- bounded proposition;
- required abstention;
- temporal applicability / precision;
- evidence locus / inference extent;
- network/territorial and law/practice notes;
- source role/direction/claim fitness;
- independence group;
- explicit adversarial-correction prose.

The ledger therefore fails the preregistered discriminator.

## Task-by-task result

### 1. Identify the exact premise(s) whose correction changed the conclusion

**Baseline: PASS on 6/6.**

For every frozen case, the source relation(s), their role/notes, and the final
adversarial correction make the relevant premise recoverable without inventing a new
relation type.

The ledger is shorter, but does not reveal a previously missing premise.

### 2. Identify all conclusions affected if one premise/source family changes

**Baseline: PASS for the frozen cases; ledger offers convenience only.**

Within each target packet, the bounded proposition and abstentions enumerate the
affected target-level conclusions. For dependency-heavy cases, `independence_group`
already identifies the shared evidentiary family.

The ledger would make a future mechanical reverse lookup easier. That is a capability
difference, not evidence of missing information in the current packet.

No frozen case demonstrates a real cross-target revision-propagation failure that the
current source-relation table cannot already locate by source/independence group.

### 3. Distinguish source evidence from project inference

**Baseline: PASS on 6/6.**

Source direction/claim fitness/role and the target-level synthesis fields already
separate source observation from Atlas inference. The ledger restates that distinction.

### 4. Material information unavailable from baseline

**0 distinct failure mechanisms meet this bar.**

The ledger adds:
- normalized reasoning-rule labels;
- explicit edge orientation;
- easier machine filtering.

It does not add a premise, source dependency, conclusion boundary, temporal fact,
spatial fact, category distinction or review correction that the baseline lacks.

### 5. Duplication / review burden

The six-case prototype requires **15 additional inference rows**.

Each row duplicates some combination of:
- target identity;
- source/premise references;
- an existing boundary already stated in proposition/abstention/notes;
- review state.

A future source or conclusion update would therefore require keeping both the ordinary
packet and inference rows synchronized.

That is a real new review atom and a new drift surface.

## Frozen threshold evaluation

Required to survive:
> material reconstructibility or revision-impact gain in at least two distinct failure
> mechanisms, without mere duplication.

Observed:
- material gain: **0 mechanisms**;
- convenience/queryability gain: **6 mechanisms**;
- added review atoms: **15 rows**;
- infrastructure required: none, but representation duplication is real.

**Disposition: REJECT.**

## What still transfers from CRMinf / factoid practice

The external precedents remain useful as a **review vocabulary**, especially:
- premise versus conclusion;
- inference activity versus source assertion;
- reasoning dependency;
- revision impact.

Those concepts can sharpen adversarial questions without becoming a new canonical
table/class.

## Reopen trigger

Reconsider an explicit inference ledger only if a real future review/update event shows
one of the following:
1. one premise/source-family change affects multiple reviewed conclusions and the
   current source/independence-group structure cannot reliably identify them;
2. reviewers materially disagree about which source premises support a conclusion even
   after reading the current packet;
3. a release update misses a conclusion that should have been re-reviewed because the
   dependency was not reconstructible from existing artifacts.

Do not reopen for:
- prettier diagrams;
- graph visualization;
- machine queryability alone;
- theoretical alignment with CIDOC CRM;
- larger corpus size by itself.
