# DISC-06 result — inference-chain stress test

**Issue:** #240  
**Disposition:** **REJECT DURABLE EXTENSION; LEARN FROM AS OPTIONAL REVIEW TECHNIQUE**  
**Historical subject research:** none  
**Canonical release:** v0.6.1 unchanged

## Finding

A 15-relation minimal inference ledger was constructed over six already-reviewed cases
with known correction mechanisms.

It made premise → conclusion relationships easier to scan, but it did **not** add
material reconstructibility or revision-impact information unavailable in the current
portable packet in any of the six failure mechanisms.

The preregistered threshold required material gain in at least two distinct mechanisms.

**Observed material gains: 0.**

The current packet succeeds because the correction-critical distinctions are already
owned explicitly by:
- temporal applicability/precision;
- target-specific locus and inference extent;
- dimension separation;
- required abstention;
- source direction/claim fitness;
- source independence groups;
- adversarial correction records.

## Strongest negative result

A source-level inference ledger is actually too coarse for the cases where a richer
model might matter. Nālandā and Cahokia require distinguishing multiple **assertions
inside a source** before formal inference edges become more informative.

That would require a durable source-assertion/factoid layer, additional identifiers and
review workflow. DISC-06 did not earn that complexity.

## Consequence

Do **not**:
- add an inference table to the canonical/experimental portable contract;
- adopt CRMinf/RDF;
- create a knowledge graph/graph database;
- introduce factoid objects merely to make the ledger work.

Do:
- retain CRMinf/FPO as external conceptual precedents;
- allow disposable inference notes during difficult review if useful;
- reopen only on demonstrated many-to-many revision-impact failure or a concrete
  machine-readable consumer need.
