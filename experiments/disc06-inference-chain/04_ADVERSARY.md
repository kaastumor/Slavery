# DISC-06 adversarial review

## Assumption under attack

The preliminary result says the explicit inference ledger should be rejected as a
durable core extension.

## Attack 1 — reverse dependency lookup might still be valuable

**Finding:** true as a usability/maintenance possibility.

A machine-readable ledger can answer “which conclusions reference this premise?” more
directly than packet prose.

**Counterevidence:** the six cases do not demonstrate a correctness failure caused by
lack of that lookup. Each target has a compact, local evidence packet and the relevant
source family / temporal / dimensional boundary is already explicit.

**Disposition:** **PARK**, not promotion. Reopen if releases develop enough many-to-many
derived conclusions that source/claim changes cannot be safely impact-assessed from
the current packet.

## Attack 2 — CRMinf/FPO prove the abstraction is established

**Finding:** established external models prove that argument/factoid provenance is a
real scholarly pattern.

**Counterevidence:** external maturity does not establish this project's need. The
minimal ledger becomes semantically stronger only if we also introduce assertion-level
premises/factoids. That would add precisely the abstraction layer this experiment was
required to justify.

**Disposition:** **REJECT as current core extension; retain external precedent.**

## Attack 3 — post-hoc exposed cases unfairly favour the baseline

Because final R1 packets already include the corrections, the baseline is unusually
strong. A ledger might have prevented the mistakes earlier.

**Finding:** plausible.

**Limit:** this experiment cannot honestly prove prevention because all six cases are
exposed regression material. Encoding the known correction after the fact risks
circular success.

The proper claim is therefore only about **preservation/reconstructibility after
review**, which was the preregistered question. Prevention remains unproven.

**Disposition:** does not rescue SURVIVES.

## Attack 4 — perhaps use the ledger only during review, not in releases

A disposable reviewer worksheet could be useful without becoming canonical.

**Finding:** plausible and cheap.

**Consequence:** this is process convenience, not a new portable evidence-core
requirement. Reviewers can already use temporary reasoning notes/checklists when a case
is complex.

**Disposition:** **LEARN FROM / optional disposable technique**, not durable schema.

## Final adversarial disposition

**REJECT durable inference-ledger extension.**

The current portable packet survives the six-case reconstructibility stress test.
CRMinf/FPO remain useful conceptual references, especially if future work exposes
many-to-many inference-impact failures, but no new factoid/inference layer is earned now.

Reopening trigger:
- a reviewed source/assertion revision affects multiple published conclusions and the
  current packet cannot identify the impact reliably; or
- an external machine-readable consumer requires explicit argument dependencies and a
  bounded test shows that the need cannot be met by derived/release-time tooling.
