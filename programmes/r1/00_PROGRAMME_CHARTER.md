# R1 — Core Hardening + First Systematic Coverage Release

**Issue:** #159  
**Authorized:** 2026-09-23  
**Base main:** `cf00e6c36968ea2720f0111cdf63cc39e06ee770`  
**Canonical historical release:** `v0.6.1` remains unchanged until an explicit validated release decision  
**Programme type:** real research/release programme, not experiment

## Mission

Graduate the Historical Slavery Atlas from architecture experiments into a real, bounded research programme.

R1 must produce:
1. a hardened **Core Contract v1**;
2. one reconstructible **candidate systematic coverage release**;
3. one simple **Atlas/map + evidence-register release surface**;
4. QC, changelog and unresolved-issues artifacts sufficient to decide whether the candidate may become a new canonical/public release.

The programme does **not** succeed because it has many rows.

It succeeds only if the resulting release is:
- auditable;
- internally coherent;
- explicit about uncertainty and non-coverage;
- geographically and temporally balanced enough for its declared frame;
- reconstructible from sources and release metadata;
- safe against the failure modes already discovered by COV-001→004.

---

# 1. Programme sequence

R1 executes in this order:

## R1.0 — setup / adversarial gate
- freeze this charter;
- freeze setup adversary;
- bound Core Contract v1;
- no new historical target research before setup passes.

## R1.1 — Core Contract v1
Turn only **empirically demonstrated** rules into the programme contract.

No ontology expansion without a historical failure/consumer.

## R1.2 — target-frame freeze
Freeze the first release frame before subject research.

## R1.3 — C0 construction and target QA
Register targets, identity/time state and geometry/research state.

No slavery conclusion required.

## R1.4 — C1 research
Research the frozen stratified subset.

## R1.5 — selective C2 escalation
Apply frozen escalation rules, including source-quality failure.

## R1.6 — release QC / adversarial replay
Run release-level QC, sample replay, source-dependency and geometry checks.

## R1.7 — candidate release + simple Atlas surface
Materialize an immutable candidate release, changelog, QC summary, unresolved issues and boring map/register Atlas.

## R1.8 — release decision
Explicitly choose:
- publish/canonicalize;
- publish as noncanonical research release;
- hold for review;
- or reject/rework.

No R2 is implied.

# 2. Core Contract v1 — allowed scope

Core Contract v1 may canonize only rules with demonstrated evidence from the project.

## 2.1 Claim/research tiers

### C0 — registered target / research state
May contain:
- target identity;
- source-native identity/version;
- temporal frame;
- spatial frame;
- geometry state;
- identity-validation state;
- research state;
- reviewed-through/release state.

Must not imply:
- slavery presence;
- slavery absence;
- prevalence;
- law;
- practice.

Required public interpretation where subject research has not occurred:

> Registered target; historical slavery/coercion research not yet performed.

### C1 — compact bounded research
Must contain:
- research outcome/state;
- strongest bounded proposition;
- strongest required abstention;
- source-quality state;
- source references;
- temporal applicability/precision;
- evidence locus;
- inference extent;
- law/practice distinction when material;
- network/territorial distinction when material;
- unresolved/disputed reason;
- language/access limitation;
- review state;
- reviewed-through/release id.

### C2 — selective deep packet
Triggered only by:
- material disagreement;
- category/translation ambiguity;
- temporal back-projection risk;
- spatial/generalization risk;
- law/practice ambiguity;
- network/territorial ambiguity;
- identity/geometry uncertainty that changes interpretation;
- **source-quality failure in a decisive positive proposition**;
- or QC/reviewer escalation.

Adds richer:
- source role/direction;
- terminology/category analysis;
- contrary/limiting evidence;
- inference reasoning;
- dependency/review propagation.

C2 is not a prestige tier and is never required merely because a target is famous.

# 3. Source contract

## 3.1 Primary/secondary division

Primary sources are preferred for:
- bounded events;
- transactions;
- law;
- historical terminology;
- dates;
- locations.

Specialist secondary scholarship is preferred for:
- classification;
- prevalence;
- continuity;
- social/legal interpretation;
- category translation;
- structural claims.

Neither source type automatically outranks the other outside its evidentiary role.

## 3.2 Source-quality state

Each decisive C1/C2 source relation must be tagged:
- `production_grade`;
- `usable_with_limitation`;
- `context_only`;
- `access_limited`;
- `review_required`.

A positive bounded proposition may not depend solely on `context_only` or `review_required`.

The Chandela COV-004 failure is a permanent fixture.

## 3.3 Independence

Multiple citations do not imply independent support.

Evidence packages must distinguish:
- independent attestations;
- derivative/repeated claims;
- common-source dependence;
- synthesis based on the same underlying evidence.

Archive/document count never determines prevalence mechanically.

---

# 4. Temporal and spatial contract

Keep separate:
- target identity;
- historical jurisdiction;
- evidence locus;
- inference extent;
- geometry;
- geometry certainty.

Allowed geometry states include:
- exact/bounded;
- approximate historical;
- modern proxy;
- point;
- route/network;
- fuzzy region;
- unresolved/no geometry.

A route is never a territorial-practice polygon.

A site is never automatically a polity.

A modern polygon never silently becomes historical geometry.

Selected-year display must test historical applicability separately from source dating precision.

Neutral world land remains visible everywhere.

---

# 5. Evidence dimensions

Never collapse these into one binary field:
- territorial practice;
- legal/state status;
- external/network participation;
- research coverage;
- historical geometry.

No P0–P4 universal public intensity scale is reintroduced.

No citation/voyage/archive count mechanically sets practice intensity.

Unknown, inconclusive, unresearched and disputed remain distinct.

---

# 6. Source-to-claim dependency contract

Every published/release claim must permit traversal:

`source/version -> claim/evidence relation -> target row -> release membership`

Shared-source packets must expose all dependent rows.

A source-level correction must create explicit review propagation to every dependent claim.

Historical releases are immutable.

Corrections create:
- review tasks;
- next-release changes;
- supersession links.

They do not silently rewrite old releases.

---

# 7. R1 release ceiling — not a quota

R1 may contain **at most**:
- **120 C0 targets**;
- **36 C1 researched targets**;
- **12 C2 deep packets**.

These are stop ceilings, not success metrics.

R1 may ship fewer if:
- target-frame quality is weak;
- source access/language burden is higher than expected;
- independent review capacity is insufficient;
- QC fails;
- research value saturates.

No one is allowed to “fill the quota” by weakening source standards.

# 8. Release sampling principles

The exact target frame must be frozen in R1.2 before C1 research.

It must satisfy:

## Geography
Use a neutral sampling geography for balance, not as a historical ontology.

No research batching by crude map sector merely because sampling uses it.

## Time
Include deep-time, medieval/early modern and modern historical intervals.

R1 may deliberately exclude contemporary person-level data if the legal/privacy/ontology burden differs; any exclusion must be explicit.

## Target type
The frame must include both:
- polity/jurisdiction targets;
- non-polity targets.

Non-polity categories remain experimental and may fail/reclassify.

## Evidence richness
Target selection may not depend on known slavery evidence richness.

## Existing experimental rows
Existing COV rows may enter R1 only through explicit re-review under Core Contract v1.

They do not receive grandfathered publication status.

---

# 9. Minimum balance requirement

The candidate release may not be described as “systematic” unless its C1 research set covers:

- at least **5 distinct temporal bands**;
- at least **6 neutral geographic sampling sectors/regions**;
- at least **3 target-frame classes** including one non-polity class;
- no single geographic sector >25% of C1;
- no single time band >30% of C1.

These are release-balance constraints, not prevalence weights.

If the release cannot meet them safely, ship a narrower named scope rather than pretending global balance.

# 10. Review / QC contract

## Internal QC
Every C1/C2 must pass:
- schema/required-field validation;
- source-quality gate;
- date/applicability check;
- identity check;
- inference-extent check;
- law/practice/network separation check;
- C0/absence leak check;
- geometry-state check;
- dependency/source recovery check.

## Adversarial replay
At least:
- 25% of C1 rows;
- 100% of C2 rows;
- all positive claims based on only one decisive source;

receive a separate blinded/adversarial replay.

## Independent / multi-review boundary
R1 may produce a versioned **candidate research release** without an external human reviewer.

It may not label C1 as independently/publicly reviewed unless that has actually occurred.

If independent review is unavailable:
- release status must say so;
- QC must distinguish `internally_reviewed` from `independently_reviewed`;
- public/canonical promotion remains a separate decision.

# 11. Atlas surface contract

R1 includes a real Atlas surface, but the default is boring.

Required:
- neutral world outline;
- selected-year navigation where temporal applicability supports it;
- appropriate geometry type;
- visible C0/unresearched state;
- bounded claim text;
- source links;
- release/review state.

Allowed:
- ordinary filters;
- conventional GIS symbology;
- simple target inspection.

Not earned by default:
- bespoke claim-layer UI;
- graph exploration;
- semantic search;
- custom timeline framework;
- vector/RAG features;
- contributor platform.

A feature may enter R1 only if a repeated real research/release task cannot be handled adequately by the boring baseline.

---

# 12. Feature-discovery rule

During R1, record **friction tickets** rather than immediately building features.

A friction ticket must contain:
- repeated task;
- current boring workaround;
- concrete failure/cost/error;
- affected users/workflow;
- candidate smallest intervention.

A feature becomes eligible for a bounded test only if:
- the same friction recurs at least 3 times across independent release tasks; or
- one occurrence causes a serious correctness/provenance failure.

Features are judged against the strongest boring baseline.

---

# 13. Release gate

R1 candidate release can pass only if:

1. Core Contract v1 is frozen and decision-logged;
2. all release rows are reconstructible;
3. C0 never implies absence;
4. all C1 positive propositions meet source-quality rules;
5. all C2 triggers are resolved or explicitly unresolved;
6. source dependencies are complete for published claims;
7. QC reports no unresolved critical correctness defect;
8. release has changelog + QC summary + unresolved issues;
9. Atlas surface uses the exact candidate release, not draft tables;
10. balance claims match the actual release;
11. review level is honestly labeled.

A failed gate may produce:
- held candidate;
- reduced-scope release;
- or no release.

It must never be converted into success by deleting inconvenient QC criteria.

---

# 14. Success criteria

R1 succeeds if it produces a trustworthy release and exposes real next questions.

It does **not** succeed because:
- C0 count rises;
- map has more dots;
- more sources were collected;
- CI is green;
- code was added;
- a database grew.

Primary success signals:
- bounded claims survive review;
- disagreement/uncertainty remain visible;
- source recovery works;
- release reconstruction works;
- map does not overclaim;
- research gaps are visible;
- actual repeated friction generates a disciplined next backlog.

---

# 15. End-of-R1 decision

R1 ends with an explicit decision among:

- **CONTINUE COVERAGE** — method/release works; authorize another bounded research release;
- **CONTINUE + FEATURE TEST** — same, plus one or more earned feature experiments;
- **HOLD / REVIEW** — research core useful but review/QC not strong enough to publish;
- **SHRINK** — release useful only at narrower scope;
- **STOP** — programme does not justify continued curation.

No result automatically creates R2.
