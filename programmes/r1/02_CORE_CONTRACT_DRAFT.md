# Core Contract v1 — Draft Boundary

**Status:** DRAFT FOR R1.1 HARDENING — not canonical yet  
**Programme:** R1 / #159

This file is intentionally short.

It is a checklist of the rules that R1.1 is permitted to harden, not a new ontology.

## Allowed contract sections

1. research tiers C0/C1/C2;
2. source-quality / source-independence / source-direction separation;
3. strongest bounded proposition + strongest required abstention;
4. temporal applicability + dating precision;
5. evidence locus + inference extent;
6. law / territorial practice / network participation / research coverage separation;
7. target identity + historical jurisdiction + geometry separation;
8. geometry state including point/route/fuzzy/unresolved;
9. language/access limitation + coverage confidence;
10. source-to-claim/release dependency;
11. review state + escalation triggers;
12. immutable release/supersession rules;
13. required QC fixtures.

## Mandatory empirical fixtures

At minimum the contract must encode protections exposed by:

- Chandela — positive claim outruns decisive source quality;
- Zhu — temporal leakage from later/earlier shared literature;
- Mahdids / New Netherland / Georgia / Western Regions — identity/time mismatch;
- Kilwa — site/network evidence must not become coast-wide territorial practice;
- Silk Road / Viking — network participation must not become territorial fill;
- Samoa — retrospective category evidence must not be silently back-projected;
- Andaman — external colonial captivity must not become indigenous internal practice;
- Cluny — servile terminology must not be silently normalized;
- Cahokia — coercion/sacrifice must not automatically become slave status;
- C0 fixtures — unresearched must never become absence;
- Sabaean time split — later scholarship must supersede through release history rather than rewriting old state.

## Explicitly excluded from Core v1 unless a concrete R1 failure requires them

- universal intensity score;
- generic actor graph;
- RDF/CIDOC/PROV layer;
- vector embeddings/RAG;
- custom review platform;
- generalized world-history ontology;
- new map interaction framework;
- predictive inference;
- automated absence detection.

## Exit rule for R1.1

Core Contract v1 is ready to freeze when:
- every rule maps to a fixture or required release consumer;
- every fixture has at least one machine-checkable or review-checkable invariant;
- no unresolved schema concept is required merely “for later”;
- the contract can be explained without reference to application implementation.

Any unresolved nice-to-have is deferred.
