# Verified checkout without shell credentials

When git clone/ls-remote cannot obtain shell credentials but authorized GitHub connector reads succeed, use this path. It is NOT permission to bypass a denied connector/repository read. Never request/purchase credentials or substitute another identity after an actual permission denial.

1. Read current canonical revision C and Git commit tree T through the connector; inspect ownership/WIP before work. Fetch Git tree T recursively and require truncated=false. If the tree has symlinks/submodules or another unsupported mode, this helper stops; do not silently omit those paths.
2. Use an isolated temporary directory with manifest.json, blobs/, checkout.py and a NEW repo/ destination. Fetch checkout.py at the exact operational ref. Manifest is {repository, revision:C, tree_sha:T, truncated:false, tree:[the exact recursive entries]}. Do not modify tracked source files in place.
3. For each unique tracked blob, fetch_file(repository_full_name, path, ref:C, encoding:"base64"). Require returned sha equals tree entry SHA. Store {sha, encoding, content, size:treeEntry.size} in blobs/SHA.json without displaying source contents. Batch independent reads in code mode; keep writes sequential. Cache only within this invocation unless durable authenticated reuse is independently verified.
4. GitHub contents responses may return empty content for files >1 MiB even with encoding=base64. If nonzero expected size has empty content, explicitly fetch https://api.github.com/repos/OWNER/REPO/git/blobs/SHA. This connector returns decoded UTF-8 text for that endpoint. Store its EXACT structuredContent.content string with encoding:"utf-8"; never JSON.parse/reserialize a JSON source file. Binary large files unsupported by that read must BLOCK; never reconstruct or omit them.
5. Run python checkout.py manifest.json blobs repo in that isolated directory. The helper verifies paths, modes, decoded sizes, Git blob hashes and the entire Git tree hash before declaring success. Do not ignore any mismatch. Destination reuse is refused. The first real Needle validation retrieved 772 tracked files / 15,030,434 bytes and matched tree 7d6e9bb0d62f96a3818459ac0574b9af70e710b5 exactly; this is evidence for that revision, not a hardcoded current tree.
6. This creates an actual isolated Git working tree with a LOCAL baseline commit. Its tree equals the canonical source tree. Full history is NOT reconstructed and local HEAD is NOT canonical revision C. Report both separately. Use C as remote publication parent/base; never use local HEAD as a GitHub parent. History-dependent checks/archaeology must use actual remote history; this snapshot cannot substitute.
7. Run task-relevant checks and proportionate sanitation/build on the full verified tree. Inspect actual diff. Publish authorized changes through Git data/working-branch PR preparation with expected canonical parent/tree and non-force protection. Do not require shell push credentials when the authorized connector publication already works.
8. A newly verified checkout capability is a real prerequisite change for a checkout-BLOCKED stage. Resume its fixed stage/input using dependency_changed=true only after verifying this capability in the current runtime and re-reading actual main/ownership. Keep earlier negative receipts and verified effects; do not repeat their operation IDs. A changed main requires explicit input/scope reconciliation.

No Python/runtime, unavailable connector, truncated tree, unsupported object, bad hashes, incomplete files or an actual permission denial means BLOCKED. This is a checked source-materialization fallback, not fake test/checkout evidence or a relaxation of privacy/merge/browser/production gates.
