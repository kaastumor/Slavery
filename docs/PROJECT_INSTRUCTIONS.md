# Project Instructions

## Canonical source

The canonical project repository is **`kaastumor/Slavery`**. Inspect current `main`, `BACKLOG.md`, open issues/PRs and current CI before relying on chat summaries, remembered context or an older handoff.

For continuation, read repository-root `BACKLOG.md`, the active protocol/checkpoint,
and `discovery/DISCOVERY_EXECUTION.md`. On first entry also read the charter and
these project instructions. Read `24_WAY_OF_WORKING.md` for a consequential process
choice; consult the relevant Project Health entries and decisions when their evidence
could change the decision. Do not reread the entire archive every run.

For a reusable session prompt use `discovery/RUN_PROMPT.md`. Scheduled work also
uses `automation/hourly-worker.md`. The model setting does not alter evidence gates.

Before data/schema/methodology changes, also read the relevant canonical method/source/data/geography/decision/architecture documents.

## Durable methodological constraints

- Preserve the current canonical data release unless explicitly creating and validating a new version. Do not overwrite historical releases.
- The atlas is evidence synthesis/data curation, not a generator of novel historical theory where specialist scholarship already resolves the question.
- Keep territorial practice, legal status, external/network participation, research coverage and historical geometry separate.
- Unknown/inconclusive/missing geometry is not absence.
- Never infer actor nationality/political identity from flag, registration, port, residence, business base, surname or company jurisdiction.
- Never derive territorial-practice intensity mechanically from archive, voyage, document or citation counts.
- Use primary/source-native evidence mainly for bounded events/facts and specialist scholarship for classification/prevalence/structure; preserve contrary evidence and dependency.
- Evidence is claim-specific. Preserve temporal/spatial uncertainty and source-native values.
- Historical geometry does not prove slavery/coercion. Prefer accepted specialist geometry over the global fallback only through the documented bounded review.
- Draft/reviewed/published/canonical states remain separate.
- Methodology/ontology/schema changes require a Decisions Log entry before becoming canonical.
- Every release requires changelog/QC/unresolved-issues/provenance sufficient for reconstruction.

## Operating rule

Use the evidence loop in `24_WAY_OF_WORKING.md`. Prefer the smallest useful experiment that materially changes belief. **Do not optimize for returning to idle.** After each bounded horizon, reconcile evidence and select one next high-information research/discovery experiment under WIP=1. Treat failure, simplification, redirection or stopping as valid experiment outcomes, but not as the default scheduling state. Elapsed time is not a scarce-resource stop rule; evidence quality, focus and project complexity are.

Do not create a second backlog, risk register, roadmap or decision system beside the canonical repository structures.
