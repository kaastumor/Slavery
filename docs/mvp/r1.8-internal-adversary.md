## Blocking finding

### Committed candidate artifact was stale

The committed file web/public/data/r1-mvp-candidate.json on main did not contain the current MVP contract.

It lacked:
- overview_semantics;
- temporal_navigation;
- geometry_manifest.

The current web/src/mvp.ts requires those sections.

### Why CI missed it

The Web MVP workflow regenerated the candidate before checking it. That proves the generator can produce a current artifact, but it does not prove the committed artifact was already current.

A stale committed file could therefore pass CI because CI repaired it before checking it.

This matters because the R1 candidate is supposed to be a deterministic, inspectable, committed static artifact.

## Bounded repair

The R1.8 rework is limited to release integrity:

1. regenerate and commit the exact candidate bundle from the frozen R1 inputs;
2. make CI run build_mvp_candidate_bundle.py --check before regeneration;
3. add a regression test that the committed bundle bytes equal canonical_bytes(build()).

No historical data, classification, geometry, ontology or feature behavior changes.
